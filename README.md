## Structure

**Control Plane**: 1x 3gb ram, 1 Ampere Core, 50gb storage

**Worker Nodes**: 3x 7gb RAM, 1 Ampere Core, 50gb storage

**OS:**  Talos 1.13.4 (latest)

**Talhelper config**:

```yaml

kubernetesVersion: 1.36.1
endpoint: ${CONTROL_PLANE_IP} # or ${VIP_CONTROL_PLANE_IP}

  - ${CONTROL_PLANE_1_IP}

  - hostname: worker-1
```

## Initial Setup

First, install Talos to all nodes. After that, write a talconfig.yaml, similar to the one above. Use

```shell
talhelper genconfig
```

 to generate the talos config files. Talhelper is kinda overkill for this setup, but it's better to have a proper file to check on instead of wrapping everything in a command. It's also not that much

After generating the config files for the instances, you need to apply them using

```shell
talosctl apply-config --insecure -n ${NODE_IP}
```

The endpoint is already declared in the config file, so you don't need the -e flag. Same for the talosconfig file containing the certs. That's why talhelper is good here.

Next, you need to bootstrap the control plane. Depending on setup, you would need a VIP (Virtual IP) for multiple control nodes, but i only use one. With

```shell
talosctl bootstrap -n ${CONTROL_PLANE_IP} --talosconfig talosconfig
```

you bootstrap etcd for the control plane, which is fundamental for this to work at all. The `talosconfig` file can be found in the `clusterconfig` folder that gets generated by `talhelper genconfig`.


To finish this setup and aquire your kubeconfig file, now run

```shell
talosctl kubeconfig --nodes ${CONTROL_PLANE_IP} --talosconfig talosconfig -e ${CONTROL_PLANE_IP}
```

To check that everything works, now run

```shell
export KUBECONFIG=$PWD/kubeconfig
kubectl get nodes
```

You should see something like this:

```shell
NAME             STATUS   ROLES           AGE   VERSION
controlplane-1   Ready    control-plane   22m   v1.36.1
worker-1         Ready    <none>          22m   v1.36.1
worker-2         Ready    <none>          22m   v1.36.1
worker-3         Ready    <none>          22m   v1.36.1
```

It looks like this

```shell

  name: sealed-secrets-key4wm2z
  namespace: kube-system
  labels:
    sealedsecrets.bitnami.com/sealed-secrets-key: active

  tls.crt: SECRET
  tls.key: SECRET
```

 You apply it using

```shell
kubectl apply -f sealing-key.yaml
```

That's it. Just make sure to do this before anything else. This should be top prio after you get the system up and running.

If the command is successful, the terminal output should look like this:

```shell
secret/sealed-secrets-key4wm2z created
```


## Installing ArgoCD

ArgoCD is the bread and butter of this setup. I prefer ArgoCD just because i like the WebUI, nothing more. It's battle tested and widely used, therefore no worries regarding stability.

First, create the ArgoCD namespace by running

```shell
kubectl create namespace argocd
```

After that, you need to install ArgoCD. To make this as idiot-proof as possible for future me, you just need to do the following

```shell
git clone https://github.com/Thewolf2068/homelab.git
cd homelab
kubectl apply -k bootstrap/argocd/
```

That will install ArgoCD to the argocd namespace. To access the WebUI, you can run

```shell
kubectl port-forward svc/argocd-server -n argocd 9091:443
```

This will open the ArgoCD WebUI [here](https://localhost:9091)

The default username is admin, the default password can be found by running

```shell
kubectl -n argocd get secret argocd-initial-admin-secret -o jsonpath="{.data.password}" | base64 -d
```

Just the output without the  **%**  at the end

## Bootstraping the core infrastructure

This is pretty simple. From the homelab directory that you cloned ealier just run

```shell
kubectl apply -f root-app.yaml	
```

This will deploy all of the infrastructure, includign but not limited to

- Longhorn
- Velero
- SMB-CSI Driver
- Traefik
- Cert-Manager
- Sealed Secrets

Go check in the WebUI for when those are all healthy. Might take a minute or two, especially the certificates for the domain. Just be patient, it should all work


## (Optional) Restore Backup

I use velero to back up all of my service storage. So for jellyfin, arr stack, etc. To restore that, install the velero cli from your preferred package manager. After that, run

```shell
velero get backups
```

This should give you a list of all backups saved to S3 storage. Just pick the name of the newest one and do

```shell
velero restore create ${RESTORE_NAME} --from-backup ${BACKUP_NAME}
```

That's it.


## Bootstrap workloads

Just as simple as the core infrastructure. Just run

```shell
kubectl apply -f workloads-app.yaml
```

This deploys everything that is not core infrastructure like jellyfin, audiobookshelf, navidrome, etc.

And that's it.
